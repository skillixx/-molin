## 五、缺陷 #2 最终复测结果：**已修复，验证通过 ✅（核心验证点，重点关注）**

**复现步骤（与前两轮完全一致）**：
1. 创建一个商品（product_id=14, plan_id=14），配置默认价 `20.00` +
   会员专属价（`membership_level_id=qa_gold(id=1)`）`6.00`；
2. 创建账号 A（VIP 会员 user_id=43，含有效 `user_memberships` 记录，
   `status=active`，`expires_at=2026-07-07`，未过期）和
   账号 B（非会员 user_id=44，同角色 `qa_e2e_member_role`，**无** `user_memberships` 记录）；
3. 两账号均完成实名认证、余额充值至 200.00，分别下单购买该商品。

**本轮实际结果**：

```
PASS  VIP 会员下单返回成功 → amount=6
PASS  VIP 用户购买会员价应用 → 按会员价 6.00 扣费（实际扣减=6）
非会员下单返回：HTTP 403, body={'code': 40003, 'message': '无购买权限', 'data': None}
PASS  非会员下单被拦截 → HTTP 403（与预期"非会员无法购买"一致）
```

**数据库交叉验证**（`orders`、`wallets` 表）：

| user_id | 角色 | 是否有有效会员记录 | 订单结果 | 扣费结果 |
|---|---|---|---|---|
| 43（VIP） | qa_e2e_member_role | 是（`user_memberships.status=active`，未过期） | 订单 #49，`status=paid`，`amount=6.00` | 余额 200.00 → 194.00（扣减 6.00，与会员价一致） |
| 44（非会员） | qa_e2e_member_role（同角色） | 否（无 `user_memberships` 记录） | **未生成针对 product_id=14 的订单**（仅有充值订单 #48，`product_id=NULL`） | 余额保持 200.00（**未发生任何扣费**） |

- 账号 A（VIP）：`HTTP 200/201, amount=6` —— 符合预期，按会员价正常成交（会员定价隔离正常）；
- 账号 B（非会员）：`HTTP 403, code=40003, message=无购买权限` —— **被正确拦截**，
  既未生成订单，也未产生任何扣费，余额、流水均无异常变化。

**结论**：缺陷 #2【P1/设计缺口】"非会员无法购买会员专属应用"业务规则**已彻底修复，验证通过**。
后端工程师丙的修复方案（复用 `product_role_access`/`PurchaseService` 现有访问控制框架，
基于 `product_prices.membership_level_id` 数据判定"会员专属"商品；购买时校验用户是否拥有
匹配等级且 `status=active` 且未过期的 `user_memberships` 记录，否则返回 `403/40003`）
精准落地，**返回码、错误码、拦截时机、数据一致性均与设计预期完全相符**，
该缺陷在最终验收中转为通过，第一阶段验收用例 #11 状态由"不通过"→"**通过**"。
