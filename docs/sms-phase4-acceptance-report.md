- 安全复审补充 P1：短手机号、短邮箱或异常账号可能绕过展示层掩码；现已使用登录日志专用失败关闭脱敏器并补否定用例。

  非可信直连只认 `RemoteAddr`，并补轮换伪造头仍在第十一次返回 429 的回归用例。
- P2：管理后台本地代理硬编码、文档状态冲突、错误文案/作用域冲突、Redis 错误语义不清、用户端代理缺测试均已修复。
- 产品经理已接受拆分的 P2：auth 权威兼容契约仍要求手机验证码使用 `verification_codes.target_value`；改为 HMAC 需要
  新 migration 和停发窗口，本阶段没有 migration 授权。短信日志、Redis、响应和审计已保持脱敏。
- 产品经理已接受拆分的 P2：新代码不再写入完整登录账号，但历史 `user_login_logs` 不会在无维护窗授权时自动回填；
  建议作为独立数据治理任务处理，阶段 4 只验收新写入路径。

产品经理书面决定：以上两个 P2 均不在本阶段无 migration/维护窗授权下暗改。前者另立手机目标 HMAC 化、
