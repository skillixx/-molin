# AI 网关 G8 回滚手册

> 回滚不得删除、覆盖或伪造请求账本、Usage、价格快照、钱包流水、hold、Outbox、审计、申诉或监控历史。

## 1. 触发条件

- 任一 P0/P1、非零正常账单差额、重复扣费、负余额或无法追踪结算。
- 未释放 hold、Outbox/补偿不收敛、内容审核失败开放或结果未知自动重试。
- 成功率低于灰度门禁、Bifrost 双节点不可用、监控/告警不可用、备份或恢复验证失败。
- 密钥泄漏信号、越权、日志正文泄漏或客户范围超出授权。

## 2. 顺序

1. 固定事件 ChangeId，停止扩大范围，将 `AI_GATEWAY_TRAFFIC_ENABLED=false`。
2. 保留活动请求与财务事实，等待已发送请求按可信 Usage 收敛；结果未知保持 hold 并进入审计核定。
3. 切换到已验证旧应用/路由/配置，禁止执行 destructive down migration。
4. 验证旧版本 health/ready、TLS/SSE、指标、Bifrost、Redis/RabbitMQ 和日志。
5. 运行只读对账；差额非零时继续保持流量关闭，不直接 SQL 修账。
6. 如需恢复新版本，重新执行完整关闭态门禁，不复用失败请求的幂等键进行盲重试。

## 3. 恢复判定

旧版本可启动、健康检查通过、监控可用、三项差额为 0、异常/积压收敛、密钥事件已轮换/吊销并经 QA 复核后，才可申请新的灰度授权。

## 4. 演练证据

记录新→旧→新三个制品摘要、每次启动 PID/容器 ID、health/ready、数据库 schema、只读对账、活动告警和恢复耗时。隔离演练不得伪装为生产回滚成功。
