# 阿里云短信验证码阶段 4 安全报告

## 1. 安全结论

阶段 4 修复了三个安全缺口：手机发码缺少手机号+场景服务层冷却、手机验证码缺少最大错误次数、公开手机
发码/密码重置的 IP 桶曾信任可伪造的 `X-Forwarded-For`。
另修复管理后台本地开发默认连接共享测试服务器的环境隔离缺陷。

CI 后独立复核未发现 P0/P1 残留；GitHub Actions run `30891459024` 的五个 Job 全部通过。

## 2. 安全控制

| 控制 | 结果 |
|---|---|
| 验证码存储 | 只保存 SHA-256 哈希，不保存明文 |
| 验证码状态 | `pending → accepted/failed`；只有 accepted、未过期、未使用记录可消费 |
| 一次性消费 | MySQL 原子更新；并发只能一次成功 |
| 错误次数 | 校验前原子取得资格；手机号 HMAC + scene，十分钟最多五次，并发不能越界 |
| 发码冷却 | 手机号 HMAC + scene，60 秒一次，Redis Lua 原子执行 |
| Redis 故障 | 发码门禁失败关闭为 503；消费门禁失败关闭并统一为 400 验证码错误 |
| IP/用户限流 | IP 桶使用 `TRUSTED_PROXY_IPS` 可信来源解析器且永不读取 XFF；服务层再叠加手机号+场景维度 |
| 供应商重试 | SDK 自动重试关闭，避免不确定重复发送 |
| 模板选择 | 只接受审核通过、本地启用、变量精确为 code 的独立绑定 |
| 日志 | 完整手机号不入发送日志；只保留 masked + HMAC |
| 登录日志 | 手机号和邮箱账号在写入 `user_login_logs` 前脱敏，查询层继续二次保护 |
| 功能开关 | 默认 `SMS_ENABLED=false`，关闭态不创建可用验证码、不调用 Sender |
| 邮箱隔离 | 邮箱继续使用 DirectMail Sender，不进入短信 Sender |
| 管理员 MFA | 普通 403 不跳转；只有冻结三元组进入 MFA |
| 环境隔离 | 两个 Vite 控制台本地开发均默认本机 API，且各有防回归测试 |

## 3. 供应商错误与外部边界

超时、供应商限流、签名错误、模板错误、账户异常、网络中断和普通拒绝均转换为安全类别；业务响应不返回
供应商原始 body、AccessKey、请求签名或完整手机号。发送失败后验证码转为 `failed`，不得消费。

`accepted` 只代表供应商受理。页面和文档均不得将其描述为送达或真实收件。

## 4. 敏感信息处理

代码、测试和文档不得持久化真实 AccessKey、Bearer Token、JWT、密码、验证码或完整手机号。浏览器验收只使用
测试数据和临时令牌；CLI 生成的临时快照、日志和截图在验收后已整目录删除。

当前工作树已执行 Git 差异敏感词、完整大陆手机号、AccessKey、Bearer 值和 JWT 形态扫描，新增/修改内容均为
0 命中；`git diff --check`、Go 模块校验、两端契约测试、类型检查、Lint 和生产构建均通过。PR #320 已由
GitHub Actions 在 Linux 隔离环境重复执行并通过，且没有以本地扫描替代 CI。

## 5. 残余风险

1. Windows 本机无法执行 Go race；已由 GitHub Actions Linux CI 覆盖。
2. 本机无隔离 MySQL/Redis；真实并发约束和 TTL 已由 CI 服务容器覆盖。
3. 仓库前端依赖审计存在既有 moderate/high 项，需要独立供应链升级计划。
4. 阶段 4 未部署和未发送真实短信，不能证明本次提交在部署态的阿里云受理或真实收件。
5. auth 模块现行兼容契约要求手机验证码行继续使用 `verification_codes.target_value`；短信发送日志、Redis key、
   响应和审计均不得保存完整手机号。若后续要将该兼容列改为 HMAC，需要单独 migration、停发窗口与兼容授权，
   不得在本阶段无 migration 授权下暗改。
6. 新代码会在写入 `user_login_logs` 前脱敏标准和异常手机/邮箱账号；既有部署库的历史登录账号不会被本阶段
   自动回填。历史脱敏需要单独备份、维护窗、脚本与授权，本报告只证明新写入路径。
7. 隔离或生产环境若经反向代理访问 API，部署验收必须把该代理实际连接地址显式写入 `TRUSTED_PROXY_IPS`，
   并确认代理覆盖 `X-Real-IP`、删除 XFF/Forwarded；否则应用会安全地按代理 `RemoteAddr` 共用一个限流桶，
   可能造成误限流。当前未获部署授权，不能把本地直连测试冒充反向代理配置验收。
