# AI 网关 G7 可靠性与可观测性功能说明

> 状态：代码与本地隔离验收已完成，测试环境、CI、独立评审、QA、产品验收和 PR 合并状态以 `docs/ai-gateway-g7-acceptance.md` 为准。

## 1. 功能目标

G7 面向运维、测试、财务核对和产品验收人员，为已完成的文字模型商业链路补齐“看得见、能告警、可核对、可演练”的可靠性门禁。G7 不新增客户收费能力，不改变 G6 用户页面，也不开放生产流量。

核心结果：

1. 在既有 `/api/internal/metrics` 输出 AI 网关低基数指标，覆盖请求量、端到端耗时、流式首 Token、上游结果与重试、Usage 缺失、流式断连、治理拒绝、并发租约、账务状态、预占、Outbox、补偿任务和账单差额。
2. 提供 Prometheus 告警和 Grafana SLO 看板，集中展示 99% 可用性目标、P50/P95/P99 延迟、P95 TTFT、Bifrost 双节点、财务一致性和任务积压。
3. 提供 `ai-gateway-reconcile` 只读账单核对命令，核对请求账本、销售 Usage、价格快照、钱包预占、结算和消费流水。
4. 提供隔离 G7 验收脚本，自动执行 1000 请求@100 并发、100 路同键幂等竞争、JSON 附加开销/SSE 首包附加开销门禁、流式断连、Fake HTTP 上游停止/恢复、Redis 停止/恢复和零差额核对。

## 2. 使用角色与入口

| 角色 | 入口 | 可执行操作 |
|---|---|---|
| 运维 | Prometheus、Grafana、只读 CLI | 查看指标、告警、SLO 和只读核对结果 |
| 测试工程师 | `infra/scripts/verify-ai-gateway-g7-reliability.sh` | 在临时容器运行可靠性、混沌和财务一致性验收 |
| 产品经理 | G7 验收文档与 Grafana SLO 看板 | 确认范围、业务口径、P0/P1 和阶段门禁 |
| 开发人员 | Go 测试与 `/api/internal/metrics` | 定位请求、上游、资源治理和账务异常趋势 |

G7 没有新增用户端或管理端按钮。Grafana 仅绑定测试服务器本机回环，远程查看使用受控 SSH 隧道；仪表盘中的时间范围、刷新、图例筛选和面板下钻均由 Grafana 提供可操作反馈。

## 3. 核心业务规则

1. 指标标签不得包含 `request_id`、用户 ID、Project ID、平台 SK、上游密钥、提示词或响应正文。
2. 逻辑模型标签必须先由数据库准入；最多保留 32 个模型，超出或非法值统一记为 `other`。
3. 首 Token 时间只在第一段审核通过的公开 SSE 数据成功写入并 Flush 后记录，不把内部收到时间伪装为用户可见时间。
4. 客户端断连只记录一次；服务仍使用独立上下文读完可信 Usage 并执行结算，不因客户端取消跳过财务终态。
5. 对账金额使用 MySQL `DECIMAL` 和 Go Decimal，禁止经过 `float64`；价格快照逐项匹配不可变价格版本和四个 SKU，Provider 原始 Usage 与四项销售 Usage 必须数量守恒，销售单价、逐项 `ceil_8` 金额、最低收费和钱包结算金额必须一致。人工核定销售用量存在时优先使用 `reconciled/sequence_no=1`，否则使用 `provider/sequence_no=1`。
6. 任一账本↔Usage、账本↔预占、账本↔钱包流水差额非零，或出现重复结算、成功未结算、缺失价格快照、缺失钱包流水、缺失 Usage、完成未收敛、账务 exception、未释放 hold、Outbox/补偿积压时，CLI 必须返回失败并输出有限条 request_id 明细。
7. 指标数据库读取失败时 `/api/internal/metrics` 返回脱敏 503，禁止输出看似健康的零值。
8. CLI 仅允许显式 `APP_ENV=local/development/dev/test/testing` 且批准值原始字节精确等于 `YES`；使用 MySQL READ ONLY、REPEATABLE READ 事务，不具备修账路径。
9. 用户账单申诉必须先校验请求归属；通用疑似密钥文本一律拒绝入库但不进入 P0 数据源，只有候选值的 HMAC 精确匹配该请求所属有效平台 SK 时，才按 API Key 写入不含明文/Hash 的 `secret_leak_detected` 审计。指标在五分钟窗口内按唯一 API Key 计数，审计失败时请求失败关闭。
10. 并发租约 Gauge 从 Redis 共享租约索引按未过期成员读取，不按 Go 实例本地计数求和；任一实例清理过期租约后所有实例抓取到同一权威值。
11. 输入与输出审核共用封闭拒绝原因；输出违规记 `content_policy`，分类器超时记 `classifier_timeout`，分类器或审核状态持久化失败记 `fail_closed`。JSON/SSE 每个失败请求只记录一次；内容策略拒绝的请求结果统一记 `rejected`，分类器超时或失败关闭统一记 `failure`，不能因协议差异绕过审核不可用或可用性告警。
12. 未释放 AI 预占按数量、金额和最老年龄观测；最老年龄超过 300 秒或总额超过 10 元均按 P1 告警。在线 Usage 缺失计数和只读对账识别的数量/单价/金额不一致均接入同一 P1 Usage 告警。

## 4. 范围边界

G7 包含已发布文字模型的测试与观测，不包含：

- 生产部署、生产 Migration、生产流量或真实客户灰度；
- 图片、音频、视频模型执行；
- 自动退款、自动补扣、自动释放异常预占或自动修改账单；
- 付费上游压力测试；负载和混沌测试只使用 Fake 上游，付费上游费用为 0。

G7 与 G8 的边界：G7 只证明测试环境文字模型的可靠性、观测、零差额和回滚能力；G8 才讨论生产部署/真实客户灰度、长期容量与成功率、生产告警路由、付费上游受控采样及图片/音频/视频模型。G7 通过不自动授权进入 G8，必须另立 Goal 和变更审批。

## 5. 验收标准

- 1000 个 Fake HTTP 请求按 100 并发全部形成唯一结算终态，成功率不低于 99%；钱包余额非负，冻结金额归零。
- 100 路相同幂等键只创建、执行、结算和扣费一次。
- JSON 直接累加 Prepare、调用上游前和上游首字节到客户端首次写出三个网关本地阶段，P95 不超过 20ms；SSE 使用“上游响应体首字节 → 首个公开数据帧成功写入”两个直接时间戳计算首包附加开销，P95 不超过 30ms；两者与数据库完整性负载分开报告。
- 流式客户端断连事实被记录，可信 Usage、价格快照、结算和钱包流水完整。
- Fake 上游停止时确认未发送的请求释放预占，恢复后同幂等键可安全重试。
- Redis 停止时失败关闭，恢复后 8 节点 100 并发仍按 20 个租约准入且最终租约归零。
- 三项金额差额为 `0.00000000 CNY`，七类聚合账单异常、未释放预占、Outbox 活跃积压和补偿活跃积压均为 0，request_id 明细为空。
- Linux `-race`、Prometheus 规则测试、Grafana 运行检查、安全测试、测试环境 E2E、独立评审、QA、产品验收和 CI 全部通过，P0=0、P1=0 后才允许合并。
