# AI 网关 G4 功能说明

## 1. 目标与范围

G4 在 G2 Project SK 鉴权和 G3 人民币可靠计量链路之前增加内容安全、分布式资源限制、Project/SK 预算和故障补偿。公开调用入口仍为 `/api/token/chat/completions` 与 `/v1/chat/completions`，客户不感知 Bifrost，也不接触内部上游密钥。

本阶段交付后端治理能力和前后端接口契约，不包含管理后台 Vue 页面、生产部署、真实用户流量或 G5 图片/视频异步任务。

## 2. 使用角色

- 小型企业客户：使用 Project SK 调用模型，收到稳定、可机器处理的拒绝或限流结果。
- 企业客户：查看本人最小化安全事件并提交申诉；预算使用展示和企业自助调整入口在后续用户端阶段交付。
- 平台管理员：设置 Project/SK 预算与四层资源上限，发布或回滚覆盖七类底线的安全策略，暂停用户或 SK，处理申诉、临时预算、补偿任务和 Outbox dead 事件。
- 运维和财务：观察预算预留、补偿任务和 G3 结算状态，不直接修改账本事实。

## 3. 请求顺序

```text
Project SK、实名、模型权限
  -> 输入内容安全
  -> G3 最坏金额报价
  -> MySQL 原子预算预留
  -> Redis 四层并发/RPM/TPM 准入
  -> G3 钱包 hold
  -> 唯一上游执行
  -> 输出内容安全
  -> G3 一次终态结算
  -> TPM 核销、租约释放、预算同步
```

任一治理依赖异常均失败关闭。Redis 或安全策略不可用时不会绕过治理调用上游。

## 4. 内容安全规则

- 覆盖违法、色情、赌博、毒品、恐怖、仇恨、自伤七类基础规则。
- 输入在报价、预算、钱包和上游调用之前审核。
- JSON 输出先完整审核再返回；SSE 按有界分段缓存审核，违规分段不会写给客户端。
- SSE 违规后仍读取可信 Usage，并以 `provider_cost` 不可变计量行保存冻结成本单价和平台成本金额；用户钱包 hold 释放、销售金额记为 0，再发送 `molin.content_policy` 和 `[DONE]`。若 Usage 暂缺则保持待对账和 hold，补录后再按同一零扣费规则收敛。
- 默认拒绝文案固定为：`请求内容违反中国大陆相关法律法规或平台安全规范，无法继续处理。`
- 安全事件只保存 SHA-256 摘要、分类、规则码、策略版本和处置结果，不保存提示词或模型正文。
- 策略采用 draft、active、retired 不可变版本；回滚会复制历史规则并生成新版本。

## 5. 资源治理规则

同时检查 user、project、api_key、model 四层限制，任一层超限即拒绝：

| 层级 | 默认并发 | 默认 RPM | 默认 TPM |
|---|---:|---:|---:|
| 用户 | 100 | 600 | 2,000,000 |
| Project | 100 | 600 | 2,000,000 |
| Project SK | 50 | 300 | 1,000,000 |
| 模型 | 500 | 3,000 | 10,000,000 |

并发使用 Redis 租约而非永久计数器；执行期间心跳续租，结束、异常或进程退出后可释放或自动过期。RPM/TPM 使用 Redis 原子脚本准入，预估 TPM 在最终可信 Usage 到达后核销。429 返回 `Retry-After` 和脱敏后的 `limit_scope`。

## 6. 预算规则

- 支持 Project 和 Project SK 两级，模式为 disabled、soft、hard。
- 日/月周期按 Project 的 IANA 时区计算。
- hard 在钱包 hold 和上游调用前原子预留，防止多节点、多 SK 并发超卖。
- soft 只产生阈值事件，不阻断请求；80%、90%、100% 每个周期各生成一次幂等事件。
- 临时增额必须包含正金额、原因、操作人和过期时间。
- 预算预留只引用 G3 的人民币报价与终态，不创建第二套钱包或消费账本。

## 7. 补偿与人工处置

- 后台每分钟扫描没有补偿任务的过期 held 预算，以及已经到达 `next_retry_at` 的补偿任务；后者不等待 24 小时预留到期。
- G3 已 settled/released 时同步预算终态；钱包 hold 前没有形成 G3 请求的过期预留可安全标记 expired。
- 日/月归属使用预算准入时固化的周期字段；请求跨午夜结算仍计入原日周期，不按完成时间漂移。
- 单条同步失败不会阻塞批次，使用唯一 `task_key` 幂等记录。
- 连续八次失败进入 dead 并停止自动扫描；manual_review 同样由人工接管。管理员可用更新时间乐观锁显式转为 retry 或 manual_review，转 retry 时才重置重试次数。
- 人工操作先写审计日志，审计失败则业务写入不执行。
- 输出审核阻断但暂缺 Usage 时，管理员通过专用受控接口补录可信 Usage；系统记录平台成本、释放用户预占，用户销售金额恒为 0。相同补录幂等，冲突补录拒绝，禁止运维直接改账本表。

## 8. 稳定错误契约

| HTTP | code | error_type | 含义 |
|---:|---:|---|---|
| 403 | 40310 | content_policy_violation | 内容违规 |
| 403 | 40311 | content_access_suspended | 用户或 SK 已暂停 |
| 429 | 42920 | budget_limit_exceeded | hard 预算达到上限 |
| 429 | 42921 | rate_limit_exceeded | RPM/TPM 超限 |
| 429 | 42922 | concurrency_limit_exceeded | 并发超限 |
| 503 | 50320 | moderation_unavailable | 内容安全依赖不可用 |
| 503 | 50321 | governance_unavailable | 预算或资源治理不可用 |

以上 G4 响应均携带 `request_id`；不返回 Redis Key、SQL、上游地址、Bifrost 路由或密钥名称。

## 9. 页面入口规划

管理后台“AI 网关”后续增加：安全策略、违规事件、访问处置、申诉、资源策略、预算策略、临时增额、补偿任务。用户可通过 JWT 分页查询本人最小化违规事件并按 event_id 申诉，后端再次验证事件归属。用户控制台页面后续增加预算使用情况、限流提示、违规事件和申诉入口。本阶段接口已经提供，页面开发另立前端任务并做桌面/平板/手机适配。
