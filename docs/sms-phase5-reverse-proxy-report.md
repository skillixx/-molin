# 阿里云短信验证码阶段 5 反向代理核验报告

## 1. 仓库静态结果

`python infra/nginx/verify_forwarded_headers.py` 已通过。`admin.conf`、`user.conf`、`api.conf` 的 API 反代均：

- 覆盖 `X-Real-IP $remote_addr`；
- 删除 `X-Forwarded-For`；
- 删除 `Forwarded`；
- 不使用 `$proxy_add_x_forwarded_for`；
- 对一次性内部 bootstrap 路径保持公开 404。

## 2. 测试服实际结果

2026-08-04 已创建专用网络 `molin-sms-proxy`（`172.20.250.0/28`，gateway `.1`），管理端固定 `.2`、用户端
固定 `.3`。运行中 API 已配置 `TRUSTED_PROXY_IPS=172.20.250.0/28`，三处 health 均为 200。

动态核验结果：非可信 localhost 直连即使伪造 `X-Real-IP` 仍按 RemoteAddr 通过内部指标双闸；经两套 Nginx
伪造 XFF 均被覆盖，内部指标请求为 403；两套公开手机发码入口在关闭态均返回 `503/50300`，Provider 指标、
发送日志、手机验证码行和应用日志完整号码计数均无增量。结论：**固定代理与关闭态可信来源链通过。**

## 4. 部署态验收矩阵

| 场景 | 期望 |
|---|---|
| 非可信直连伪造 XFF/X-Real-IP | 忽略伪造头，只按 `RemoteAddr` |
| 可信代理 + 一个合法 X-Real-IP | 使用该值作为最终来源 |
| 可信代理缺失 X-Real-IP | 403/40003，业务与供应商调用增量 0 |
| 可信代理重复/逗号多值/非法 X-Real-IP | 403/40003，业务与供应商调用增量 0 |
| 合法 X-Real-IP + 冲突 XFF/Forwarded | 只采用 X-Real-IP |
| 轮换伪造转发头 | 不能绕过第 11 次 IP 限流 |

合法 Nginx 链、直连伪造头和 XFF 覆盖已在测试服执行；缺失、多值和非法 `X-Real-IP` 的失败关闭由 Go 专项测试
覆盖，本轮未绕过 Nginx 人工构造原始可信代理请求。真实短信和第 11 次限流仍留在单独授权的 Canary 窗口。
