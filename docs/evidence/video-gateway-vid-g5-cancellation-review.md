## 已发现并修复

| 编号 | 问题 | 修复与反例 |
|---|---|---|
| G5-SUBMIT-001／P1 | CAS输家把其他Worker推进的状态当作自己获权，仍进入Provider | 单次直接CAS决定提交权；去重前入口原2现1，完整Gateway被退款抢先时入口为0 |
| G5-SUBMIT-002／P1 | 后到Submit把在途RPC改pending并丢失返回ID | 重试只读；真实SQL覆盖在途重试、取消意图、原ID绑定及之后释放；明确未知响应测试未放宽 |
| G5-CANCEL-002／P1 | 两条取消入口门禁不一致，零成本/未归档被误当无产物 | 共享门禁、独立无产物摘要证明及SQL保护；14种回执反例与后补终态不能退款 |
| G5-CANCEL-003／P1 | 双取消响应同成本摘要但产物存在性矛盾可被后者掩盖 | 成本和冲突观察原子持久化；两种到达顺序均阻断退款，不能在pending或冲突下补证明 |
| G5-CANCEL-004／P1 | 新增冲突事实未阻止原成功路径扣费/继续读取 | 确认成本读取统一检查冲突；原Usage及财务终态不回退 |
| G5-CANCEL-005／P1 | 相反成功确认冲突时新事务全回滚，观察也丢失 | 公开确认入口持Task锁；成本子事务回滚后外层提交观察，再返回原错误。真实Poll覆盖同event异body/新event Usage冲突及退款前后4例 |
| G5-POLL-001／P2 | queued轮询被误判failed | 保留本地状态，不回退、不误失败；主任务定向先红后绿 |

独立最终源码复核确认：上述公开入口均已闭合，无递归或漏接的私有成本写入入口，未发现新的直接阻断问题。运行关闭由主任务后续同版回归确认；不能将此结论扩成完整G5无缺陷。
