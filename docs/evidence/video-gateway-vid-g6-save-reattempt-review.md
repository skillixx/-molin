# VID-G6 已终止保存后的新尝试：产品工程边界

独立产品角色`vid_g6_g5_gate`只读核对原保存/清理合同及000088/89后给出以下下一步准则。这里只记录设计审查，不表示实现或测试通过，不改变商业价格、保留期限和财务政策。

- 旧幂等键永远绑定原尝试。aborted后只能返回原终止事实，不重新预占或创建对象，不因权益续期复活旧计划。
- 新键须先证明旧尝试已完成五目标清理围栏与原额度释放，再重新执行当前源、归属、政策、权益和容量准入。
- 最直接的可重试场景是原权益到期触发清理后合法续期，而源仍未到期；源过期不得为重试延长期限。
- completed仍只产生一个长期资产，新键返回既有保存。新尝试必须使用新身份和全新五目标，旧墓碑及迟到Copy拒绝保留。

现有每Task一个主键协调行、命令只指Task不足以表达多次尝试。后续迁移应演进原协调体系：增加不可变尝试身份与序号/前驱，保留原Task与全部冻结字段，命令精确指向尝试；数据库约束同Task至多一个非aborted尝试，completed仍占该唯一位置。既有命令可以依据迁移前每Task唯一记录确定性绑定，但不得回填没有证据的历史权益类型。

原aborted行、计划、容量释放、事件、清理时刻和hash不得覆盖。审计所有按task_id更新/查询的恢复路径，避免一次更新新旧两行。新尝试、命令绑定、容量预占及唯一位置争用在同一事务完成。

必须覆盖旧键零副作用、新键成功且新目标不同、100个新键唯一尝试/资产/容量、cleanup_pending或确认未知禁止重试、旧清理与迟到Copy不影响新预占、每写点及COMMIT未知恢复、completed重放、跨主体/异Task冲突、迁移重复up/保留down与旧行关联，以及跨全部尝试的容量合计。
