# 团队任务分配表

## 1. 你首先要做什么

你现在不要先让开发人员直接写 GPU、Agent、Skills、Token。

你第一步应该先确定 6 件事：

1. 确定第一版团队名单。
2. 确定技术栈：`Vue3 + Go + MySQL + Redis + RabbitMQ`。
3. 确定第一版只先跑通一个售卖闭环。
4. 确定角色和权限点。
5. 确定商品、订单、钱包、资产的状态流转。
6. 确定每个人负责的模块边界。

第一批开发目标：

```text
邮箱/手机号注册登录
  -> 用户角色权限
  -> 统一商品
  -> 订单钱包
  -> 用户资产
  -> 一个普通应用售卖闭环
```

这个闭环没跑通前，不建议大规模开发 GPU、Agent、Skills、Token。

## 2. 功能类型划分

建议把所有功能分成 8 类：

```text
账号权限类
商品交易类
用户资产类
内容运营类
资源业务类
AI 业务类
前端页面类
运维测试类
```

每一类都有明确负责人，避免所有人都在改同一块代码。

## 3. 推荐人员配置

最低配置：

- 后端 1：账号权限。
- 后端 2：商品交易。
- 后端 3：资产、会员、应用接入。
- 前端 1：管理后台。
- 前端 2：用户控制台。
- 测试 / 产品：规则、验收、测试。
- 运维：环境、部署、CI。

如果人员不足，可以合并：

- 后端 1 负责账号权限 + 内容运营。
- 后端 2 负责商品交易 + 用户资产。
- 前端 1 先做管理后台。
- 前端 2 先做用户控制台。

## 6. 第二周任务

第二周目标是让后台可以配置商品，用户端可以看到商品。

重点：

- 权限中间件。
- 商品 CRUD。
- 套餐 CRUD。
- 价格配置。
- 用户端商品列表。
- 用户端商品详情。

第二周结束应该验收：

```text
管理员创建商品
  -> 配置套餐
  -> 配置价格
  -> 配置角色权限
  -> 用户登录
  -> 用户看到可购买商品
```

## 7. 第三周任务

第三周目标是跑通购买闭环。

重点：

- 订单创建。
- 钱包扣费。
- 财务流水。
- 用户资产生成。
- 用户资产查询。
- 购买成功页面。

第三周结束应该验收：

```text
用户购买商品
  -> 创建订单
  -> 扣钱包
  -> 生成流水
  -> 生成资产
  -> 用户看到资产
  -> 管理员看到订单和流水
```

## 8. 不建议第一周做的事情

第一周不要做：

- GPU 调度。
- Agent 定制。
- Skills 市场。
- Token 聚合网关。
- 复杂报表。
- 分库分表。
- Kubernetes。
- 多租户复杂审批。

这些都依赖基础闭环，太早做会拖慢整体进度。
