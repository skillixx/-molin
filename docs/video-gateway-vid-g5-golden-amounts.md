# VID-G5 非商业金额金样

## 功能与使用范围

本文件用于开发者、测试和财务合同复核，验证十二种Fake视频结果的真实持久化账本行为。所有钱包、主体、价格、Provider确认及媒体都是本地非商业夹具；没有正式HTTP入口、真实Provider支出、真实钱包或部署。

原始观察值见[金额数据](./evidence/video-gateway-vid-g5-golden-amounts.json)，包括Request/Task/Quote关联、Usage来源及数量、资金流水数量和金额、钱包前后余额、Outbox、资产、补偿与逐项对账差异。数据不是从批准表复制，来自隔离MySQL中的实际执行结果。

## 十二种金样

每例初始可用余额10、冻结0，名义5秒；金额单位CNY，均为合成金额。未入账表示没有该条事实，JSON保留null，不写假零。

| 编号 | 结果 | Hold | 销售已入账 | 成本已记录 | 净释放 | 可用余额后 | 冻结后 | 补偿 |
|---|---|---|---|---|---|---|---|---|
| F01 | T2V成功 | 0.50 | 0.50 | 0.20 | 0 | 9.50 | 0 | 无 |
| F02 | I2V成功 | 0.75 | 0.75 | 0.30 | 0 | 9.25 | 0 | 无 |
| F03 | 输出审核拒绝 | 0.50 | 0 | 0.20 | 0.50 | 10 | 0 | 无 |
| F04 | 明确失败且无产物 | 0.50 | 0 | 0 | 0.50 | 10 | 0 | 无 |
| F05 | Provider成功但归档失败 | 0.50 | 未入账 | 0.20 | 0 | 9.50 | 0.50 | pending |
| F06 | 结算失败后补偿成功 | 0.50 | 0.50 | 0.20 | 0 | 9.50 | 0 | completed |
| F07 | queued且未提交时取消 | 0.50 | 0 | 0（网关证明） | 0.50 | 10 | 0 | 无 |
| F08 | Provider确认取消且无产物 | 0.50 | 0 | 0（Provider确认） | 0.50 | 10 | 0 | 无 |
| F09 | Provider拒绝取消，仍执行 | 0.50 | 未入账 | 未确认 | 0 | 9.50 | 0.50 | 无 |
| F10 | 取消意图后迟到成功 | 0.50 | 0.50 | 0.20 | 0 | 9.50 | 0 | 无 |
| F11 | 结果未知 | 0.50 | 未入账 | 未确认 | 0 | 9.50 | 0.50 | retry |
| F12 | Provider报6秒、媒体5秒 | 0.50 | 未入账 | 0.24 | 0 | 9.50 | 0.50 | manual_review |

F01/F02/F06/F10为六类资产available；F03保留一份隔离主产物；F12保留六类未交付资产及6秒/5秒两份事实。其余没有可交付资产。F07的成本0来自未提交证明，不伪称Provider确认。

另有两个中间快照，不计入十二例汇总：

- F06_before_recovery：结算事务回滚后销售/结算未入账、冻结0.50、六资产temporary、补偿pending；随后从原事实完成结算和交付。
- F12_before_review：冲突首次编排后的pending；随后使用两个不同的合成主体认领人工核对并进入manual_review，不解除Hold、不覆盖成本或媒体事实。

F11真实执行一次本地补偿Worker后进入retry，Provider Submit仍为1。所有已提交案例Submit为1，F07为0；补偿不创建新Provider任务。

## 汇总与对账语义

| 范围 | 请求数 | Hold合计 | 销售合计 | 已知成本小计 | 未知成本请求数 | 净释放 | 仍冻结 | 可用余额合计 |
|---|---|---|---|---|---|---|---|---|
| T2V | 11 | 5.50 | 1.50 | 1.24 | 2 | 2.00 | 2.00 | 106.50 |
| I2V | 1 | 0.75 | 0.75 | 0.30 | 0 | 0 | 0 | 9.25 |
| 合计 | 12 | 6.25 | 2.25 | 1.54 | 2 | 2.00 | 2.00 | 115.75 |

三个范围均满足Hold=销售+净释放+仍冻结，资金守恒差异为0。八个已闭合请求逐项对账通过；F05/F09/F11/F12保留非零最终对账差异，禁止交付。因此“汇总守恒”不等于“T2V所有请求最终闭合”，已知成本小计也不是完整成本或真实Provider费用。

## 开发与验证

- 执行器：`server/internal/modules/token_gateway/service/video_golden_mysql_test.go`，使用真实Service/Repository/MySQL，外部边界仅Fake。
- 观察器：`video_golden_observer_mysql_test.go`，严格检查来源/kind/序号及钱包动作数量，不能靠同量重复Usage或零金额额外流水混过预期未闭合场景。
- 隔离运行：`VIDEO_GATEWAY_G5_TEST_FOCUS=golden`配合原000077验证脚本；该模式输出14条低敏JSON观察值和3条汇总，默认all也包含金样测试。
- 独立校验：`python scripts/verify-video-gateway-vid-g5-goldens.py docs/evidence/video-gateway-vid-g5-golden-amounts.json`。
- 篡改测试：`python -m unittest discover -s scripts -p test_video_g5_goldens.py -v`，覆盖27种篡改及JSON重复字段拒绝。

独立Python校验器使用冻结字面预期与Decimal复算汇总，验证的是导出证据内容，不替代数据库执行或完整阶段验收。回滚只关闭相关测试装配，不能删除原账本、成本、调整或审计事实。
