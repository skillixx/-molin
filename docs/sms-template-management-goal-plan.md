## 2. 可直接创建的 Goal

### 2.2 Goal 目标

## 3. 背景与当前系统现状

当前系统已经具备手机号验证码相关的业务入口，但验证码服务只负责生成、哈希保存和校验验证码，尚未调用真实短信供应商：

- `VerificationService.Send` 生成 6 位验证码，保存哈希并设置 10 分钟有效期，然后将明文验证码返回给上层。
- 非生产环境的发送接口可以返回验证码，生产环境不会返回。
- 验证码存储已经支持未使用、未过期、单次消费的原子校验。
- 当前公开手机号验证码场景为注册、登录、找回密码。
- 换绑手机和管理员二次验证分别使用受认证保护的专用发送接口。
- 公共发送接口已有基于 IP 的限流，换绑和管理员验证接口已有基于用户的限流。
- `infra/.env.example` 已预留部分短信供应商、AccessKey、签名和注册/登录模板变量，但后端配置模块尚未加载这些配置。
- 当前后端依赖中没有阿里云短信 SDK。
- 管理后台目前没有短信模板页面、路由、菜单、接口封装和类型定义。
- 当前数据库只有验证码表，没有短信模板快照、业务场景绑定和短信发送日志表。

这意味着“申请一个阿里云 AccessKey 和模板 ID”并不足以完成接入。正式上线至少还需要企业资质、短信签名、五个审核通过的模板、密钥配置、后端发送适配、场景绑定、失败处理、权限、审计、测试和发布控制。

## 4. 首期业务范围

### 4.1 本期必须完成

1. 接入阿里云短信发送能力，只用于中国大陆验证码短信。
2. 为五个验证码场景分别配置模板：
   - 用户注册：`register`
   - 用户登录：`login`
   - 找回密码：`reset_password`
   - 换绑手机：`bind_phone`
   - 管理员二次验证：`admin_verify`
3. 从阿里云同步已申请的短信模板及审核状态。
4. 在墨灵后台完成模板查询、详情查看、场景绑定、本地启停和测试发送。
5. 记录短信提交结果、供应商请求标识、错误码和审计信息。
6. 保持现有验证码接口路径和前端业务流程兼容。
7. 为短信模板管理新增细粒度权限，并通过 migration 绑定管理员角色。
8. 完成后端测试、前端构建与五态检查、接口测试、安全检查、测试验收和产品确认。

### 4.2 本期不做

- 不在墨灵后台直接申请、修改或删除阿里云侧模板。
- 不开发营销短信、通知短信、群发任务和用户运营活动。
- 不开发多短信供应商路由、自动切换或价格比选。
- 不开发国际短信。
- 不开发完整费用分析、套餐余额看板和账单对账。
- 不把短信送达回执作为首期上线前置条件；首期只记录“供应商已受理/提交失败”。
- 不改造邮箱验证码为短信发送；手机和邮箱发送链路必须保持隔离。

## 5. 核心设计原则

### 5.1 双方数据权威边界

| 数据 | 权威来源 |
|---|---|
| 模板编码、模板正文、模板类型、阿里云审核状态、驳回原因 | 阿里云 |
| 业务场景与模板的绑定关系、本地启用状态 | 墨灵平台 |
| AccessKey 和 AccessKey Secret | 环境变量或密钥管理服务 |
| 验证码明文 | 只在生成到发送调用之间短暂存在，不持久化、不写日志 |
| 发送提交结果和供应商请求标识 | 墨灵平台发送日志 |

### 5.2 场景与模板规则

- 五个业务场景分别使用独立模板，不能用一条含糊文案覆盖全部用途；管理 API 必须拒绝把同一模板绑定到多个启用场景，并在并发争用时保证最多一个场景成功。
- 每个模板统一使用 `${code}` 变量，实际变量名以阿里云审核通过的模板为准。
- 同一场景在同一时刻只能绑定一个已启用模板。
- 只有阿里云审核通过且变量满足场景要求的模板才能绑定和启用。
- 阿里云模板同步以“供应商 + 模板编码”为幂等键，不得重复创建本地模板。
- 模板被阿里云禁用、删除或审核状态变化时，同步后必须反映真实状态；已失效模板不得继续发送。
- `SendSms` 返回成功只表示阿里云已受理请求，管理端文案必须显示“提交成功”，不能描述成“已送达”。

### 5.3 建议模板文案

以下文案仅用于申请时参考，最终以阿里云审核结果为准：

| 场景键 | 建议模板名称 | 建议用途文案 |
|---|---|---|
| `register` | `molin_register_code_v1` | 您正在注册墨灵平台，验证码为 `${code}`，10 分钟内有效，请勿泄露给他人。 |
| `login` | `molin_login_code_v1` | 您正在登录墨灵平台，验证码为 `${code}`，10 分钟内有效，请勿泄露给他人。 |
| `reset_password` | `molin_reset_password_code_v1` | 您正在重置墨灵平台登录密码，验证码为 `${code}`，10 分钟内有效，如非本人操作请忽略。 |
| `bind_phone` | `molin_bind_phone_code_v1` | 您正在变更墨灵平台绑定手机号，验证码为 `${code}`，10 分钟内有效，如非本人操作请及时检查账号安全。 |
| `admin_verify` | `molin_admin_verify_code_v1` | 您正在进行墨灵后台管理员安全验证，验证码为 `${code}`，10 分钟内有效，请勿泄露给他人。 |

五条申请必须分别获得不同的阿里云模板编码；模板类型均为验证码，变量集合精确包含 `code`，并使用已经核验的固定签名。若阿里云审核要求调整措辞，产品经理需逐场景确认修改后的正文仍能明确表达对应用途，禁止退回一条通用文案覆盖五个场景。脱敏核验表至少记录场景键、模板名称、模板编码后四位、审核状态、变量、签名一致性和核验时间，不记录 AccessKey 或完整手机号。

## 6. 目标架构

```text
注册/登录/找回/换绑/管理员验证
              │
              ▼
      现有验证码业务服务
      ├─ 场景与频率校验
      ├─ 生成验证码
      ├─ 哈希存储
      └─ 调用短信发送端口
              │
              ▼
       阿里云短信适配器
      ├─ 读取场景绑定
      ├─ 组装模板参数
      ├─ 调用 SendSms
      ├─ 解析供应商结果
      └─ 写入脱敏发送日志
              │
              ▼
          阿里云短信

管理后台 → 短信模板管理 API → 模板快照/场景绑定/发送日志
                         └──→ 阿里云模板查询与同步 API
```

短信供应商调用应通过稳定的内部发送端口隔离。业务服务不得直接依赖阿里云 SDK，以便测试替身、故障处理和后续扩展；但首期只实现阿里云一个适配器，不提前建设复杂的多供应商路由。

建议配置项如下，名称需由后端甲结合现有配置结构最终确认：


签名只允许来自运维安全配置或后端维护的“已审核签名”记录。首期管理后台不提供自由输入或修改签名的输入框，避免把未审核文本带入发送链路。

## 8. 权限与角色设计

建议新增权限：

| 权限码 | 能力 |
|---|---|
| `sms:template:view` | 查看模板列表、详情、场景绑定和脱敏发送记录 |
| `sms:template:manage` | 修改场景绑定及本地启停状态 |
| `sms:template:sync` | 从阿里云同步模板 |
| `sms:template:test` | 向白名单手机号发起测试发送 |

权限必须通过新的 seed migration 写入权限表，并绑定平台管理员角色。后端接口必须校验权限；前端菜单和按钮权限仅用于交互控制，不能替代后端鉴权。

同步、绑定、启停和测试发送必须写审计日志。测试发送属于高风险动作，应同时要求管理员已完成二次验证、白名单校验、频率限制和明确确认。

## 9. 后端数据设计要求

以下为概念模型，后端甲必须在实现前完成字段、索引、约束和 migration 设计评审，并使用基于最新 `main` 的下一个可用 migration 编号。

### 9.1 `sms_templates`：短信模板本地快照

建议包含：供应商、模板编码、模板名称、模板类型、模板正文、变量定义、供应商审核状态、驳回原因、供应商更新时间、本地启用状态、最后同步时间、创建时间、更新时间。

关键约束：

- 供应商和模板编码唯一。
- 模板正文和审核状态由同步更新，管理后台不可直接篡改。
- 未审核通过的模板不可启用或绑定。

### 9.2 `sms_scene_bindings`：业务场景绑定

建议包含：场景编码、模板 ID、签名、启用状态、版本、创建人、更新人、创建时间、更新时间。

关键约束：

- 场景编码唯一，确保每个场景最多一个当前绑定。
- 更新绑定需要事务或乐观锁，避免并发配置覆盖。
- 绑定变更必须记录审计日志。

### 9.3 `sms_send_logs`：短信发送记录

建议包含：业务场景、脱敏手机号、手机号不可逆哈希、模板编码、签名、供应商、业务请求 ID、供应商请求 ID、供应商返回码、提交状态、失败原因摘要、创建时间。

安全要求：

- 不保存验证码明文。
- 不保存完整手机号。
- 不保存 AccessKey 或签名请求原文。
- 失败原因只保存经过清洗的供应商错误摘要。
- 根据安全与运营要求确定数据保留周期和归档清理策略。

### 9.4 现有验证码记录调整

阶段 1 必须先完成验证码表的最小兼容 migration，再开发真实发送链路；不得把该 migration 延后到阶段 2。最小调整至少解决：

- 当前验证码哈希使用 SHA-256 十六进制结果时需要 64 字符存储，现有长度 16 不足；后端甲须选择兼容历史数据的 64 字符列或等价二进制方案，并提供升降级验证。
- 新增可表达 `pending/sent/failed` 的发送状态及业务请求标识；状态字段对历史记录的默认值、回填范围和过期数据处理必须写入 migration 说明。
- 手机与邮箱必须采用显式分支：启用真实短信后的新手机记录只允许 `sent` 校验；历史记录及邮箱记录的兼容策略必须由后端甲在实现文档和测试中单独说明，不能把邮箱错误接入短信适配器，也不能用“默认 sent”掩盖实际未投递。
- 阶段 1 即创建 `sms_send_logs` 最小可用表并作为脱敏发送结果的权威持久化来源；阶段 2 只在兼容基础上完善筛选索引、管理查询和保留策略，不延后建表，也不以临时结构化日志替代发送记录。

手机验证码发送过程调整为明确状态流转：

```text
生成并保存待发送验证码
  → 调用供应商
  → 成功：标记 sent，允许后续校验
  → 失败：标记 failed，不允许校验，可按规则重试
```

启用真实短信后的手机验证码校验必须只接受发送成功、未使用且未过期的记录。数据调整需要兼容历史记录，并避免出现“短信发送失败但验证码仍可使用”的情况。阶段 0 未批准历史数据与邮箱策略前，不得开始 migration 实现。

## 10. 后端接口前置契约

下列接口是供后端甲评审的候选契约。前端甲不得直接以本节为最终 API 文档开发；后端甲需要先把批准后的字段、错误码和权限写入 `docs/full-api-design.md` 与 `docs/frontend-api-reference.md`，再由前端对接。

| 方法 | 路径 | 权限 | 用途 |
|---|---|---|---|
| GET | `/api/admin/sms/summary` | `sms:template:view` | 查询模板与场景全局概览 |
| GET | `/api/admin/sms/templates` | `sms:template:view` | 分页查询模板，支持审核状态、启用状态和关键词筛选 |
| GET | `/api/admin/sms/templates/{id}` | `sms:template:view` | 查看模板详情、变量及同步信息 |
| POST | `/api/admin/sms/templates/sync` | `sms:template:sync` | 从阿里云幂等同步模板 |
| GET | `/api/admin/sms/scenes` | `sms:template:view` | 查询五个业务场景及当前绑定 |
| PUT | `/api/admin/sms/scenes/{scene}` | `sms:template:manage` | 更新指定场景绑定和启用状态 |
| PATCH | `/api/admin/sms/templates/{id}/status` | `sms:template:manage` | 修改模板本地启用状态 |
| POST | `/api/admin/sms/templates/{id}/test-send` | `sms:template:test` | 向白名单手机号测试发送 |
| GET | `/api/admin/sms/send-logs` | `sms:template:view` | 分页查询脱敏短信提交记录 |

接口统一要求：

- 列表返回遵守 D-95 扁平分页结构：`{items,page,page_size,total}`。
- 请求和响应遵守现有统一响应、Request ID 和错误码规范。
- 写操作支持参数校验、权限校验、二次验证要求、审计和清晰错误提示。
- 同步操作幂等。测试发送必须要求 `Idempotency-Key` 请求头：同一管理员、模板、场景、脱敏手机号身份和相同 key 的重复请求返回首次业务请求结果，不再次调用阿里云；相同 key 携带不同业务参数返回 `409/40900`。前端防重复点击和后端限流不能替代该语义。
- 测试发送的 `scene` 必须属于该模板当前已启用的 `bound_scenes`；未绑定或绑定停用返回 `409/40900`，禁止任意模板冒充其他业务场景。
- `sign_name` 由服务端从已审核配置或绑定中读取，场景更新接口和测试发送接口均不得接受自由文本签名；管理端只读展示。
- 供应商错误不得原样暴露密钥、签名原文或内部堆栈。

现有用户端验证码 API 路径应保持不变，避免破坏注册、登录、找回密码、换绑手机和管理员二次验证页面。若响应字段确需变化，必须先更新权威 API 文档并同步两个前端。

## 11. 管理后台页面规划

### 11.1 页面入口

在管理后台侧边栏新增：

```text
消息管理
  └─ 短信模板
```

页面路由需要同时校验管理员登录、管理员二次验证和 `sms:template:view` 权限。

### 11.2 页面组成

首期采用“列表页 + 详情抽屉”的紧凑结构：

1. 顶部概览：模板总数、审核通过数、已启用数、未绑定场景数。
2. 筛选区：关键词、阿里云审核状态、本地启用状态、业务场景。
3. 模板表格：模板名称、模板编码、审核状态、绑定场景、本地状态、最后同步时间、操作。
4. 场景绑定区：展示五个固定场景及当前模板，允许有权限的管理员重新绑定。
5. 详情抽屉：显示模板正文、变量、审核信息、驳回原因、同步时间和脱敏测试记录。
6. 操作按钮：同步模板、启用/停用、绑定场景、测试发送。

### 11.3 前端文件建议

- `web/admin-console/src/views/sms/SmsTemplateListView.vue`
- `web/admin-console/src/api/sms-admin.ts`
- `web/admin-console/src/types/sms-admin.ts`
- 更新 `web/admin-console/src/router/index.ts`
- 更新 `web/admin-console/src/components/layout/SideMenu.vue`

### 11.4 前端交互要求

- 列表、详情、同步、绑定和测试发送均具备加载态、空态、错误态、成功态和无权限态。
- 同步和测试发送防止重复提交。
- 绑定前明确显示场景、模板、只读已审核签名和审核状态；首期页面不得提供签名自由输入；停用已绑定模板时二次确认并说明影响。
- 测试发送只接受后端允许的白名单手机号，页面不得缓存手机号。
- “供应商受理”显示为“提交成功”，不能显示“发送成功”或“送达成功”。
- 无对应权限的菜单、按钮和数据入口需要正确隐藏或禁用，但最终安全仍以后端校验为准。
- 延续现有 Element Plus 和管理后台视觉规范，不另建独立样式体系。
- 适配 1440、1024、768 和 390 像素宽度；窄屏下筛选区换行，表格允许横向滚动，抽屉宽度和操作区不得溢出。

## 12. 分阶段执行计划

### 阶段 0：资格、契约与基线确认

责任角色：产品经理、后端甲、运维、前端甲。

任务：

1. 以脱敏可核验证据确认阿里云企业资质、签名及五个模板均已审核通过；无证据保持阻塞，不得批准。
2. 确认测试手机号白名单、费用预算和环境隔离方案。
3. 后端甲确定内部短信发送端口、错误模型、验证码状态流转和数据库设计。
4. 后端甲完成管理端 API 正式契约、错误码和权限码设计，并更新两份权威 API 文档。
5. 运维确定密钥注入、`SMS_ENABLED`、阿里云 endpoint、手机号 HMAC、测试模式、测试白名单和生产/测试隔离方案，并明确禁止模板编码环境变量。
6. 前端甲完成 `docs/frontend-task-admin-console.md` 中短信任务的契约可实现性评审，不提前编写依赖未定接口的页面逻辑。
7. 统一手机发码响应及测试模式语义，消除 `sent/expires_in/business_request_id/submit_status` 与旧 `data:null/code` 描述冲突。
8. 明确测试发送 `Idempotency-Key`、重复请求、签名来源和场景匹配规则。
9. 解决验证码哈希列长度、历史记录回填以及邮箱发送状态兼容策略。
10. 拉取远端 `main` 并记录基线 commit；SSH host key 或权限失败时不得声称已与最新 `main` 对账。

交付物：批准的接口契约、阶段 1 最小可用表/migration 与完整数据设计、配置清单、正式前端任务单、阿里云准备项证据、远端 `main` 基线和测试策略。

阶段门禁：测试工程师确认契约可测，产品经理确认五个场景与业务文案；未通过不得进入阶段 1。

### 阶段 1：短信数据基础与关闭态发送链路

责任角色：后端甲、运维。

任务：

1. 先执行并验证 `verification_codes` 最小兼容 migration，解决验证码哈希长度和手机 `pending/sent/failed` 状态；明确历史记录和邮箱兼容行为。
2. 同阶段创建 `sms_templates`、`sms_scene_bindings`、`sms_send_logs` 最小可用表及仓储，使发送链路从一开始只读取数据库绑定；表结构须能被阶段 2 管理 API 直接扩展，不建立临时双重来源。
3. 扩展配置加载与启动校验，补齐第 7 节全部配置并保留默认关闭的功能开关；禁止读取模板编码环境变量。
4. 在 auth 范围内建立短信发送端口及阿里云适配器，引入官方 Go SDK；发送服务只读取数据库中已审核模板快照和当前有效场景绑定。
5. 只在手机号验证码流程调用短信发送，邮箱流程不得被错误接管。
6. 调整验证码发送状态，确保供应商失败时验证码不可用。
7. 对超时、限流、签名错误、模板错误、账户欠费和网络异常进行分类处理。
8. 写入最小可用脱敏发送日志和必要监控指标，不记录验证码、完整手机号和密钥。
9. 保持功能开关关闭，使用仓储 fixture 和供应商 Mock 验证五场景选择、状态流转和错误处理；阶段 1 不以 Mock 冒充真实阿里云验证。
10. 补充 migration、仓储、服务、适配器和现有 auth 回归测试。

阶段门禁：四类最小表 migration 升降级、哈希存储、历史/邮箱兼容、仓储约束和五个场景 Mock 用例通过，并证明 `SMS_ENABLED=false` 时不会提交真实短信。阶段 1 不要求也不批准真实阿里云发送；测试工程师通过后由产品经理确认，不通过不得进入阶段 2。

### 阶段 2：模板同步绑定、管理 API 与真实短信验证

责任角色：后端甲。

任务：

1. 在阶段 1 最小表结构上完善索引、约束和查询能力；不得重建验证码字段或引入模板环境变量。
2. 创建四个权限码的 seed migration 并绑定管理员角色。
3. 先实现阿里云模板查询与幂等同步，使已审核模板进入唯一权威快照。
4. 实现场景查询与绑定 API，通过受控管理操作为五个场景建立当前有效数据库绑定；禁止人工 SQL 作为生产配置流程。
5. 实现概览、模板列表、详情、本地启停、测试发送和脱敏发送记录接口。
6. 实现审核状态校验、唯一绑定、并发更新保护、测试白名单、频率限制、`Idempotency-Key` 重放和参数冲突检测。

9. 更新后端模块说明、完整 API 文档、前端 API 参考和测试指南。
10. 补充权限、参数、幂等、并发、异常、审计与真实链路验收记录。

阶段门禁：API 契约测试、安全测试、权限绕过测试和五场景数据库绑定测试通过；Mock 不证明阿里云可用，`Code=OK` 只证明受理，真实手机收到正确签名、场景文案和验证码才证明收件。测试工程师和产品经理确认后才能进入阶段 3。

## 13. 测试矩阵

| 类别 | 必测内容 |
|---|---|
| 正常流程 | 五个场景均能使用各自模板提交短信，正确验证码只能消费一次 |
| 模板同步 | 首次同步、重复同步、模板新增、审核状态变化、驳回原因更新 |
| 场景绑定 | 未绑定、正常绑定、并发修改、绑定未审核模板、停用已绑定模板 |
| 参数校验 | 非法手机号、非法场景、缺失模板变量、非法模板 ID、空请求 |
| 权限安全 | 未登录、未完成二次验证、缺少四类权限、伪造前端按钮请求 |
| 频率限制 | 同 IP、同用户、同手机号和测试发送的频率限制及恢复时间 |
| 供应商异常 | 超时、网络中断、限流、签名错误、模板错误、欠费、未知错误 |
| 数据安全 | 响应、日志、审计、数据库均无 AccessKey Secret、验证码明文和完整手机号 |
| 兼容回归 | 注册、登录、找回密码、换绑手机、管理员二次验证及邮箱验证码流程 |
| 前端体验 | 加载、空数据、错误、成功、无权限五态及四档宽度适配 |
| 发布回滚 | 开关关闭、配置缺失、migration 回滚、供应商故障时的业务降级提示 |

自动化测试不能替代真实阿里云环境验证。真实短信验证必须使用受控白名单和小流量，并在验收报告中明确区分：本地测试、测试替身、阿里云已受理、实际手机收到短信。

## 14. 安全红线

1. 禁止在源码、Git 历史、文档、前端构建产物和日志中出现真实 AccessKey Secret。
2. 禁止生产接口返回验证码明文。
3. 禁止日志和审计记录验证码、完整手机号、签名请求原文或认证 Token。
4. 禁止管理后台读取或展示 AccessKey。
5. 禁止仅依赖前端权限隐藏，所有管理接口必须执行后端权限校验。
6. 禁止没有限流、白名单和审计的测试发送接口。
7. 禁止短信发送失败后仍允许对应验证码通过校验。
8. 禁止使用阿里云主账号长期 AccessKey。
9. 禁止在生产环境自动回退到固定验证码或模拟发送。
10. 禁止把“阿里云受理”描述为“用户已收到”。

## 15. 发布与回滚方案

### 15.1 发布顺序

```text
数据表与权限 migration
  → 后端部署，SMS_ENABLED=false
  → 同步模板并绑定五个场景
  → 管理后台部署
  → 白名单真实短信验证
  → 监控确认
  → SMS_ENABLED=true 灰度放量
```

### 15.2 回滚触发条件

- 阿里云提交失败率持续超过项目设定阈值。
- 注册、登录或管理员验证出现大面积失败。
- 出现权限绕过、验证码泄露、密钥泄露或完整手机号日志。
- 模板场景错配造成用户收到错误用途文案。
- migration 或接口变更导致现有认证流程不可用。

### 15.3 回滚动作

1. 立即关闭 `SMS_ENABLED`，停止新短信提交。
2. 保留故障期间的脱敏日志和审计证据，不删除问题数据。
3. 视问题范围回滚应用版本；数据库回滚必须先确认不会破坏已产生的发送记录。
4. 管理后台隐藏或禁用高风险写操作，但不能把前端禁用当成后端止损手段。
5. 向用户显示明确的暂不可用提示，生产环境不得回退到显示验证码。
6. 完成原因分析、修复、回归和重新验收后再恢复灰度。

## 16. 最终验收标准

以下条件必须全部满足：

- [ ] 阿里云企业资质、签名和五个验证码模板均可用。
- [ ] 五个业务场景各自绑定正确的审核通过模板。
- [ ] 现有验证码接口路径和主要响应契约保持兼容。

## 17. Goal 执行纪律与报告格式

### 17.1 每次执行前

1. 读取根目录 `AGENTS.md` 和当前责任模块的 `CLAUDE.md`。
2. 检查当前分支、最新 `main`、远程差异和未提交文件。
3. 确认上一阶段测试验收与产品经理确认已经完成。
4. 确认本次只修改本角色负责的模块，不覆盖其他开发者改动。
5. 确认所依赖的正式 API 文档已经更新并合并。

### 17.2 每阶段报告

```text
阶段：
基线 commit：
执行角色：
完成任务：
修改文件：
新增或变更的接口/权限/migration：
本地自动化验证：
真实阿里云验证：
未验证事项：
风险与阻塞：
待测试工程师验收项：
待产品经理确认项：
```

报告必须区分本地测试、模拟供应商测试、阿里云接口受理和真实手机收件结果，不得把未执行或未验证的内容描述为通过。

### 17.3 停止条件

出现以下任一情况时，Goal 应暂停当前依赖任务并报告，不得自行扩大权限或绕过流程：

- 缺少阿里云短信资质、签名或任一必要场景模板。
- 真实密钥未通过安全配置提供。
- 正式 API 契约、数据库设计或权限码未批准。
- 上一阶段测试验收或产品确认未完成。
- 当前处于 `main` 且尚未创建 feature 分支。
- 工作区存在与当前任务重叠且归属不明的修改。
- 发现密钥、验证码、手机号或认证信息泄露风险。
- 生产环境只能依赖模拟发送才能继续。
