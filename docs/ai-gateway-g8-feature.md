# AI 网关 G8 功能说明

> 状态：`G8_STAGE_ACCEPTANCE=PASS`、`G8_SOFTWARE_CLOSED_LOOP=COMPLETED`、`G8_TEST_ENV_USABLE=YES`、`G8_REAL_PROVIDER_SETTLEMENT=PASS`、`ACCEPTED_EXCEPTIONS=YES`。G8 仅覆盖已经发布的文字模型链路；本文不代表生产部署、客户开放或商业验收。

## 1. 使用角色与目标

- 运维：以关闭态部署可追溯制品，执行生产等价预演、灰度和回滚。
- AI 网关管理员：发布已获产品/财务批准的 5～8 个文字模型、两个上游、价格和路由。
- 财务/产品：核对人民币价格、成本、保护汇率、最低收费、毛利和逐请求账务事实。
- 设计客户：在单独生产授权后，以 Project SK 完成真实 API 集成。

G8 将 G7 的可靠性、零差额和可观测能力收敛为可运行软件与生产形态，并设置三个分别判定、顺序递进的里程碑：

- `G8_ENGINEERING_READY`：代码、CI、隔离演练、独立评审、QA、产品验收和 PR 合并全部完成；不代表生产开放。
- `G8_SOFTWARE_CLOSED_LOOP`：测试环境部署真实候选，API 与依赖运行正常，完整用户旅程、计量扣费、账单对账、异常处理和回滚均通过，QA 与产品签收且 P0/P1=0。达到后可完成当前软件实现任务。
- `G8_COMMERCIAL_ACCEPTED`：后续另获生产与真实费用授权，完成受控灰度及商业观察，满足客户、成功率、账务和毛利门禁。该里程碑不再阻塞当前软件闭环验收。

## 2. 核心业务规则

1. 生产文字流量由 `AI_GATEWAY_TRAFFIC_ENABLED` 控制，生产默认关闭。
2. 开启生产流量前必须同时满足 5～8 个已发布文字模型、至少两个健康渠道、逐模型有效价格和健康路由、唯一生效内容安全策略、成本未过期、毛利不低于批准值；未另行批准时底线为 15%。
3. 渠道健康检查默认只允许公网 HTTPS；拒绝 loopback、link-local、RFC1918、IPv6 本地地址、DNS 重绑定和重定向。测试 Bifrost 内网地址只能用精确白名单放行。
4. 结果未知请求不得自动重试或跨上游切换；只有明确 `request_not_sent` 且 `result_unknown=false` 的失败可在同一路由配置上限内安全重试。
5. request、Usage、价格快照、hold、freeze、settle/release、钱包流水和 Outbox 继续以 G7 只读对账为事实门禁；正常账单三项差额必须严格为 0。
6. 回滚只切换应用、路由或总闸，不删除或覆盖请求账本、Usage、价格快照、钱包流水、Outbox、审计或申诉事实。

## 3. 页面与接口

- 管理端继续使用 AI 网关模型、渠道、价格、路由、安全、资源、预算、异常和监控页面。
- 用户端继续使用模型市场、模型详情、Project/SK、Quick Start、Usage、账单与申诉页面。
- 新增公开错误：`503/50330 ai_gateway_traffic_closed`。总闸关闭时不得自动重试。
- 不新增图片、音频、视频、多模态异步任务、GPU、Agent、Skills 或公开自助支付入口。

## 4. 验收

- 1440、768、375 三种视口无横向溢出，所有按钮具备加载、成功、失败或禁用反馈。
- 真实后端浏览器旅程覆盖管理员发布、用户模型发现、Project/SK、调用、Usage、账单和申诉；Mock 仅作补充。
- 原严格基线要求测试环境 P0/P1=0、正常账单差额=0、运行态无 UNKNOWN、回滚可用，并由测试工程师和产品经理签收；本次最终归档由项目负责人以 `ACCEPTED_EXCEPTIONS=YES` 明确覆盖尚未按原路径补录的运维项，具体例外与延期边界以第 5 节为准，不得反向伪造为测试通过。
- 商业观察周期与成功率目标在后续生产灰度立项时单独确认，不作为 `G8_SOFTWARE_CLOSED_LOOP` 的完成条件。

## 5. 最终验收边界

- 已有技术证据覆盖真实 Provider、执行、Usage、结算、钱包流水、Outbox 与低敏证据持久化主链路。
- `RESPONSE_MATCH=NO` 和未配置临时 SK 的手工脚本由项目负责人接受为非阻断；前者不等于内容验收通过，后者不要求补发 Chat。
- 账单/争议追加核对接受关闭；测试服对账、失败补偿、双闸门、回滚演练、Prometheus/Grafana、告警规则、备份周期与 RabbitMQ ready 消息转入后续运维专项。
- 测试服真实流量闸门保持开启，使用该能力可能触达真实 Provider 并产生真实费用，必须继续遵守独立授权、费用上限与零重试约束。
