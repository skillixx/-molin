## 开发前强制检查（每次开始新任务时）

```bash
# 1. 拉取最新 main
git checkout main && git pull origin main

# 2. 确认当前不在 main 上操作（强制要求）
git status

# 3. 按上方分支规划表创建分支
git checkout -b feature/backend-a-{模块}-{功能描述}

# 4. 确认当前分支不是 main
BRANCH=$(git branch --show-current)
if [ "$BRANCH" = "main" ]; then
  echo "错误：禁止在 main 分支上开发！请先创建 feature 分支。"
  exit 1
fi
echo "当前分支：$BRANCH"
```

## 代码规范

- 代码注释必须使用中文
- 每个模块目录结构：`model/` → `repository/` → `service/` → `handler/` → `dto/` → `route.go`
- 跨模块调用只能通过 `service` 层接口，不直接访问其他模块的 `repository`
- 错误码规范：40001=未登录 / 40002=token 过期 / 40003=无权限 / 40000=验证码错误 / 40900=账号已存在 / 42900=频率超限

## 安全规范（违反即为严重缺陷）

1. **Refresh Token**：DB 只存 `HMAC-SHA256(token, REFRESH_TOKEN_SECRET)`，明文只返回给客户端一次，不入库
2. **身份证号**：只存 `HMAC-SHA256(id_card_no, ID_CARD_HMAC_SECRET)` 和 masked 值（前6后4，中间 `********`），原始值不入库，禁止用 SHA-256/MD5 直接 hash
3. **密码**：使用 `bcrypt(cost=12)` hash，禁止明文存储
4. **验证码**：10 分钟过期，使用后写入 `used_at`，不可二次使用
5. **登录限流**：10 次/分钟/IP，超限返回 429

## 权限计算顺序（IAM，必须严格按此顺序实现）

```
1. user_permission_overrides effect=deny  → 直接拒绝（最高优先级）
2. user_permission_overrides effect=allow → 直接通过
3. 角色聚合权限                           → 通过 / 拒绝
4. 默认拒绝
```

## 权限缓存规范

- Redis key：`perm:user:{userID}`
- TTL：5 分钟
- 必须在以下操作后主动失效缓存：修改用户角色、修改角色权限、修改用户权限覆盖
