## 开发前强制检查（每次开始新任务时）

```bash
# 1. 拉取最新 main
git checkout main && git pull origin main

# 2. 确认当前不在 main 上操作（强制要求）
git status

# 3. 按上方分支规划表创建分支
git checkout -b feature/frontend-b-{功能描述}

# 4. 确认当前分支不是 main
BRANCH=$(git branch --show-current)
if [ "$BRANCH" = "main" ]; then
  echo "错误：禁止在 main 分支上开发！请先创建 feature 分支。"
  exit 1
fi
echo "当前分支：$BRANCH"
```

## 技术栈规范

- **框架**：Vue 3 Composition API + `<script setup>`
- **状态管理**：Pinia（`auth.ts` 管理登录态和实名状态，`wallet.ts` 管理钱包余额）
- **路由**：Vue Router 4
- **HTTP 客户端**：Axios（统一封装在 `src/api/http.ts`）
- **TypeScript**：严格模式，所有接口响应必须有类型定义

## 用户体验关键规范

### 实名认证拦截

购买页面必须在以下两点做前端拦截（后端也会返回 70001）：
```typescript
// 在进入购买确认页前检查
if (authStore.user.real_name_status !== 'verified') {
  // 提示："请先完成实名认证"，跳转实名认证页
}
```

### 余额展示

- 钱包余额精确到分（两位小数）
- 余额不足时在购买按钮旁显示"余额不足，去充值"
- 充值成功后实时刷新余额（不需要用户手动刷新）

### 购买流程

```
商品详情 → 选择套餐 → 确认价格（按用户角色/会员等级） → 
检查实名 → 检查余额 → 确认购买（带 Idempotency-Key） → 
轮询订单状态 → 购买成功/失败提示
```

Idempotency-Key 生成规则：
```typescript
// 每次点击"确认购买"按钮时生成新 key，防止表单重复提交
const key = `${userId}-${productId}-${planId}-${Date.now()}`
```

### 敏感信息展示规范

- 身份证号：只展示 masked 值（来自后端），不允许解密展示
- 钱包流水：金额标注正负（充值为正，扣费为负）

## API 调用规范

```typescript
// Token 刷新机制（access_token 过期时自动刷新）
// 响应拦截器检测到 code=40001/40002：
//   1. 使用 refresh_token 调用 /api/auth/refresh
//   2. 更新 store 中的 access_token
//   3. 重试原请求
//   4. 如果 refresh 也失败：清空登录态，跳转登录页
```
