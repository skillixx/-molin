## 开发前强制检查（每次开始新任务时）

```bash
# 1. 拉取最新 main
git checkout main && git pull origin main

# 2. 确认当前不在 main 上操作（强制要求）
git status

# 3. 按上方分支规划表创建分支
git checkout -b feature/backend-c-{模块}-{功能描述}

# 4. 确认当前分支不是 main
BRANCH=$(git branch --show-current)
if [ "$BRANCH" = "main" ]; then
  echo "错误：禁止在 main 分支上开发！请先创建 feature 分支。"
  exit 1
fi
echo "当前分支：$BRANCH"
```

## 核心业务规范

### ProvisionHandler 接口（所有商品类型必须实现此接口）

```go
type ProvisionHandler interface {
    Provision(ctx context.Context, req ProvisionReq) (*ProvisionResult, error)
    Renew(ctx context.Context, assetID uint64, planID uint64) error
    Suspend(ctx context.Context, assetID uint64) error
    Resume(ctx context.Context, assetID uint64) error
    Cancel(ctx context.Context, assetID uint64) error
}
```

- 新增商品类型时：实现 `ProvisionHandler` 接口，在 `bootstrap/app.go` 中注册
- `provision.Provision()` 完成后必须调用 `asset.CreateAsset()` 创建用户资产
- 应用类商品开通：确认应用状态正常即可，无需启动实例

### 用户资产状态机

```
active → suspended （暂停）
suspended → active （恢复）
active → cancelled （取消/到期）
```

### 会员规范

- 会员等级通过 `membership_levels` 表管理，不硬编码
- 用户活跃会员通过 `user_memberships.status = 'active' AND expires_at > NOW()` 查询
- `product` 模块通过 `membership.GetActive(ctx, userID)` 接口获取会员信息

### 内容可见范围

- `announcements.visible_to`：all / member / role_code
- `help_articles.visible_to`：all / member / role_code
- 用户查询时需根据用户角色和会员状态过滤
